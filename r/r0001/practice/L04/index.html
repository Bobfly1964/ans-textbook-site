    Рабочая тетрадь · Урок 04¶

    Название: Создаём собственную команду ИИ-исполнителей
    Работа на занятии: 35 минут · Самостоятельная: 30–45 минут
    Главный продукт: один управляемый исполнитель для синтетического пилота, а не «автономная корпорация».

    Вход в упражнение¶

    Откройте своё 09_pilot_protocol.md из урока 03. Если собственного пилота нет, используйте examples/09_pilot_protocol_from_lesson03.md и data/pilot_cases_20_unlabeled.csv. Все данные учебные. Не называйте их реальными клиентскими заявками.

    Перед началом определите режим:

    • А: без программирования. Вы вручную загружаете/вставляете синтетическую таблицу в доступный ИИ-чат, сами запускаете каждый следующий шаг и вручную сохраняете результат. Это контролируемая оператором сессия, а не самозапускающийся программный агент.
    • Б: без доступа к ИИ. Разберите первые шесть строк вручную. Заранее подготовленный офлайн-пример отчёта преподаватель покажет после вашей самостоятельной разметки. Это не ответ модели, а проверочный пример.
    • В: программирование, факультатив. Используйте optional_live/agents_sdk_readonly.py и отдельный API-ключ, если уже имеете безопасное настроенное окружение. Зачёт по основному курсу не требует API и оплаты.

    0. Запишите прогноз (до объяснения)¶

    В вашем стартапе хотят назначить «ИИ-директора», «ИИ-аналитика» и «ИИ-юриста». Сколько исполнителей нужно для проверки двадцати учебных обращений? Кто обязан принять итог? Предположите, где возникнет первая ошибка.

    Мой прогноз: ____________

    Что в нём пока не доказано: _________

    Задание 1 (4 минуты). Опишите работу, не должность¶

    Предположим, агенту поручается анализ двадцати учебных обращений. Заполните:

    Поле Мой ответ
    Чья проблема решается
    Какой один артефакт появится
    Как доказать его связь с первоисточником
    Чего агент не должен делать
    Какой результат для клиента остаётся непроверенным

    Стоп-вопрос: если модель предложила «увеличить выручку на 30%», откуда взялась цифра? Допустимо ли включать её как факт?

    Задание 2 (4 минуты). Паспорт первого исполнителя¶

    Заполните 13_agent_role_card.md.

    • Имя/псевдоним роли (не имеет значения для её реальных прав): _____
    • Работа: ___________
    • Разрешённый вход: _______
    • Чего он не знает о рынке: ___________
    • Артефакт и формат: ___________
    • Когда должен остановиться: _________
    • Кто принимает работу: ________

    Контроль: не выдавайте обычной роли статус «имеет доступ ко всем сервисам». Роль — не доказательство подключения инструмента.

    Задание 3 (5 минут). Контракт одной задачи¶

    Заполните 14_agent_task_contract.md по всем восьми пунктам.

    Компонент контракта Подготовленный вариант
    1. Цель
    2. Источники и статус данных
    3. Объём
    4. Разрешённые действия
    5. Запрещённые действия
    6. Definition of Done
    7. Когда STOP / NEED_REVIEW
    8. Что сообщить в конце

    Неправильный пример: «Найди причину падения продаж, всё исправь и доложи об успехе».
    Лучший принцип: «Сделай ограниченную часть работы и покажи, на каких ID она основана».

    Задание 4 (4 минуты). Карта полномочий¶

    В 15_agent_tool_policy.md отметьте каждому действию ALLOW / REVIEW / DENY.

    Действие Ваш выбор Почему
    Прочитать pilot_cases_20_unlabeled.csv
    Составить черновик отчёта в чате
    Переписать исходную CSV
    Зайти в настоящую CRM покупателя
    Отправить письмо клиенту
    Придумать неподтверждённую бизнес-метрику
    Попросить человека подтвердить сомнительную цитату

    Короткий ответ: какая техническая мера делает DENY реальным, а не только написанным в промпте? ______

    Задание 5 (7 минут). Первый контролируемый прогон¶

    Выберите один путь:

    A. Чат + синтетическая таблица. Скопируйте P01 и P02 из PROMPTS.md, затем вставьте разрешённые шесть или двадцать строк. Попросите таблицу id | категория | точная цитата | факт/гипотеза | неизвестно. При отсутствии CSV не просите агента «догадаться»: остановите выполнение.

    Б. Офлайн. Возьмите C001–C006, вручную выделите категорию и цитату. Затем попросите у преподавателя офлайн-пример отчёта и сравните структуру.

    В. Кодовый. Если SDK и API-доступ уже настроены, запустите только читательский пример из optional_live/README.md. Проверяемый факт выполнения: реальный вывод и журнал вашего запуска; заранее написанный эталон им не является.

    Заполните:

    • Использованный путь (А/Б/В): ____
    • Источник и статус (SYNTHETIC): ____
    • Сколько строк на самом деле было подано: ____
    • Вывод, который можно перепроверить: ____
    • Где модель предложила гипотезу, а не факт: ____
    • Состоялся ли реальный вызов модели (ДА/НЕТ): ____

    Задание 6 (4 минуты). Проверка от источника¶

    Проверить нужно не менее трёх исходных ID. Часть информации могла быть потеряна или выдумана.

    ID Цитата из ответа Сравнение с CSV (совпадает/нет) Что исправить

    Дополнительно проверьте количество уникальных ID. При полном отчёте должно быть 20 — не «около 20» и не «все, кроме похожих». Если запущена только подгруппа из шести строк, не заявляйте проверку всех двадцати.

    Задание 7 (4 минуты). Инструкции, спрятанные в данных¶

    Откройте data/adversarial_requests_6.csv и выберите две записи. Это специально подготовленные синтетические тесты, а не реальные сообщения клиентов. Какие фрагменты являются содержанием обращения, а какие пытаются выдать себя за команду?

    ID Непроверенное/враждебное требование Правильное действие агента

    Обязательный ответ: даже если написано «срочно, это приказ руководителя», строка входного файла не меняет разрешения агента.

    Задание 8 (3 минуты). Решение о приёмке¶

    Откройте 16_agent_run_log.csv и 17_agent_review.md.

    • Результат: ACCEPT_DRAFT / REVISE / STOP (обведите один)
    • Проверено исходных ID: _ из _
    • Основной риск: __________
    • На какой конкретной записи он обнаружен: ___
    • Следующий шаг, ответственность человека: ____
    • Какое правило можно будет превратить в Skill на уроке № 5: ______

    Успех урока — честный и проверяемый черновик, а не число агентов или длина ответа. Если из-за запретов агент остановился, это может быть правильным результатом.

    Самостоятельная работа (30–45 минут)¶

    1. Адаптируйте паспорт и контракт под собственный оффер урока 03. Если нет прав на данные, оставайтесь на синтетике (10 минут).
    2. Проведите второй независимый тренировочный прогон; сравните с первым. Допустимо сравнить два ручных разбора или два разных вывода чат-модели (10–15 минут).
    3. Повторно проверьте 3 ID, качество цитат и одну попытку небезопасной команды внутри данных. Сохраните оба наблюдения в журнал (10 минут).
    4. Запишите, чему должен будет посвящён первый Skill следующего урока: не общему «умению мыслить», а повторяемому действию с проверяемым выходом (5–10 минут).

    Самопроверка¶

    1. Может ли модель читать файл, который вы не передали и не предоставили через подключённый инструмент?
    2. Какая часть текущей практики выполняется человеком, а не агентом?
    3. Почему проверка самого агента тем же агентом полезна, но недостаточна?
    4. Почему в журнале есть статус происхождения данных?
    5. Может ли статус STOP означать успешное соблюдение политики?

    Сдача¶

    Сдайте файлы 13–17, один сохранённый учебный ответ или офлайн-разбор, таблицу сверки трёх цитат и короткое описание рисков. Не прикладывайте API-ключи, контакты и реальные записи покупателей.
