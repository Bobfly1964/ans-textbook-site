    Рабочая тетрадь · Урок 03¶

    Тема: Как проверить бизнес-идею до разработки продукта
    Время практики в классе: 35 минут · Домашняя работа: 30–45 минут активного времени
    Вход: урок 02 (04_customer_profile.md, 06_evidence_register.csv, 07_problem_decision.md).
    Правило: S01–S12 и C001–C100 — искусственные данные. Они помогают учиться, но не подтверждают спрос и никогда не записываются как реальные контакты.

    Задание 1. Назовите силу сигнала (4 минуты)¶

    Отметьте COMPLIMENT / MEETING / PILOT / PAYMENT / UNKNOWN / REFUSAL. Один сигнал может требовать уточнения.

    Фраза Тип Что точно произошло, а что неизвестно?
    «Очень классный продукт, отправьте ссылку» ... ...
    «Встречаемся во вторник с директором» ... ...
    «Согласен дать 20 синтетических примеров для демонстрации» ... ...
    «Можем обсудить бюджет до 300 €» ... ...
    «Счёт получен, позже оплатим» ... ...
    «Мы уже решаем это в CRM, спасибо» ... ...

    Контрольный вопрос: чем выставление счёта отличается от его оплаты?

    Задание 2. Сформулируйте минимальный оффер (5 минут)¶

    Откройте 07_problem_decision.md. Если реальных данных ещё нет, напишите рядом «гипотеза, не проверена на рынке». Дополните:

    Поле Ваш ответ
    ICP и роль покупателя ...
    Клиентская ситуация ...
    Какой результат будет получен ...
    Что конкретно мы делаем ...
    Какой объём пилота ...
    За сколько времени ...
    Как клиент примет результат ...
    Цена как гипотеза / условие бесплатной демонстрации ...
    Что НЕ входит ...
    Где пока нет доказательств ...

    Выход: первые 120–180 слов в 08_offer_one_page.md.

    Задание 3. Соберите «ручной» пилот (5 минут)¶

    Представьте, что вы пока не умеете программировать. Составьте маршрут из шести-семи действий от приёма допустимых данных до приёмки результата. Заполните таблицу:

    Шаг Кто выполняет: человек / ИИ / программа Что проверяем Как остановить при ошибке
    Получить разрешённые 20 обращений ... ... ...
    Выделить категории жалоб ... ... ...
    Проверить все цитаты и ID ... ... ...
    Составить 3–5 наблюдений ... ... ...
    Передать заказчику ... ... ...
    Получить обратную связь ... ... ...

    Добавьте: правило о конфиденциальности и исключения из услуги. Сохраните в 09_pilot_protocol.md.

    Задание 4. Разберите коммерческие ответы вручную (7 минут)¶

    Откройте data/buyer_reactions_12_unlabeled.csv. Для первичного разбора возьмите S01, S02, S03, S04, S07, S12. Не смотрите учительский файл с готовыми ярлыками.

    ID Что дословно сказал Какое действие подтверждено Чего ещё не произошло Следующий честный шаг
    S01 ... ... ... ...
    S02 ... ... ... ...
    S03 ... ... ... ...
    S04 ... ... ... ...
    S07 ... ... ... ...
    S12 ... ... ... ...

    Ограничение: слова «готов выделить бюджет» не переписывайте как «оплатил»; «согласился на демонстрацию» не переписывайте как «купил».

    Задание 5. Проверьте ответ ИИ (4 минуты)¶

    Если ИИ доступен, передайте ему эти шесть строк и используйте промпты P03 и P04 из PROMPTS.md. Сравните три его вывода с оригиналами и запишите:

    Вывод ИИ Где исходная строка Верно / неверно / недостаточно данных Что исправить
    ... ... ... ...
    ... ... ... ...
    ... ... ... ...

    Если ИИ недоступен, попросите у преподавателя один из четырёх подготовленных ошибочных «ответов агента» и проверьте его вручную. Не придумывайте ошибку, если модель её не допустила.

    Задание 6. Рассчитайте пилот (4 минуты)¶

    Все ставки, суммы и цены синтетические, это не рекомендация рынку.

    Статья Количество × ставка Всего, €
    Работа с данными и проверка 5 ч × 25 ...
    Продажа и согласование 2 ч × 25 ...
    ИИ-запросы — 10
    Прочие переменные расходы — 15
    Итого ...
    Предполагаемая цена 240
    Разность ...

    Вопросы: «Как изменится ситуация, если проверка занимает 10 часов вместо 5?» и «Почему стоимость токенов сама по себе не показывает прибыльность бизнеса?»

    Задание 7. Предварительно объявите критерий решения (3 минуты)¶

    Закончите фразу, до будущих реальных контактов:

    Если за __ времени мы поговорим с _ релевантными покупателями и из них совершат конкретное действие , мы . Если получим противоположный результат, мы . Если не получим ни одного реального ответа, наш статус ___.

    Объясните преподавателю, почему это не статистический тест размера рынка.

    Задание 8. Примите честное решение (3 минуты)¶

    При наличии только учебных данных ваш рыночный статус — NOT_ENOUGH_EVIDENCE.

    Поле Ваш ответ
    Что известно из настоящих данных ... / данных нет
    Что показала учебная симуляция ...
    Какое предположение сейчас самое опасное ...
    Что опровергает гипотезу ...
    Следующий минимальный реальный шаг ...
    Что точно не разрабатываем до проверки ...

    Финиш: обновите или создайте 08_offer_one_page.md, 09_pilot_protocol.md, 10_demand_log.csv, 11_pilot_cost_estimate.csv, 12_next_step_decision.md. Пустые шаблоны вложены в архив в templates/my-ai-startup/.

    Домашняя работа (30–45 минут активных действий)¶

    Подготовьте два коротких сообщения: нейтральное приглашение к обсуждению пилота и ответ на вопрос клиента «сколько стоит, какие данные передавать?». При законной возможности можно отправить одно персональное сообщение подходящему человеку; факт отправки или отсутствие ответа фиксировать без ПДн. Не организуйте массовую рассылку и не используйте агентов для самостоятельной отправки сообщений.

    Подготовьте альтернативный оффер без ИИ. Возможно, полезнее исправить уведомления или одну кнопку, чем строить аналитическую систему. Объясните, что вы будете измерять, чтобы выбрать между вариантами.

    Самооценка по окончании¶

    • [ ] Я отличаю комплимент от конкретного действия покупателя.
    • [ ] Оффер описывает результат, а не набор функций ИИ.
    • [ ] У пилота есть границы, приёмка, дата, риски и остановка.
    • [ ] Реальные факты и синтетические карточки хранятся с разными статусами.
    • [ ] Расчёт стоимости учитывает труд основателя.
    • [ ] У меня есть реальный следующий шаг, который можно сделать без разработки SaaS.

    Не забудьте: в уроке 04 эти файлы станут исходным заданием для первого агента. Поэтому ясность входных данных, ограничений и критериев приёмки важнее красоты оформления.
