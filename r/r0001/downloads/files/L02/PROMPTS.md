# PROMPTS · Урок 02

**Назначение:** воспроизводимые запросы для учебного исследования проблемы клиента.  
**Версия:** 1.0 · 14.10.2026

## Важные правила перед запуском

1. Для демонстрации загружайте **только** `data/interview_notes_12_unlabeled.csv`: все его персонажи и фразы вымышлены.
2. Не добавляйте к запросам реальные персональные данные и коммерческие тайны, если у вас нет необходимых разрешений и правового основания.
3. Попросите модель сохранять **исходные ID** `I01–I12` и приводить **точные цитаты**, а не свободный пересказ под видом цитирования.
4. Никакой результат на этих данных не означает подтверждения рыночного спроса.
5. Если модель не умеет читать CSV из вложения, скопируйте ей **три строки** из файла и попросите анализировать только их.

## P01. Критическая проверка исходной гипотезы

```text
Ты — аналитик исследований клиентов маленького B2B-стартапа.
Ниже я дам три черновых файла из предыдущего урока:
гипотезу, карту процесса и показатели успеха.

Твоя задача:
1. Отдели сведения, подтверждённые наблюдениями, от моих предположений.
2. Предложи 2–3 узких начальных сегмента клиентов (ICP).
3. Для каждого различай пользователя, покупателя, согласующего доступ и конечного получателя пользы.
4. Укажи, чего НЕ хватает, чтобы выбрать сегмент.
5. Сформулируй максимум пять вопросов, которые можно изучить в реальных интервью.
6. Не называй ни один сегмент подтверждённым.
7. Не придумывай информацию о компаниях, рынке, ценах или реальных клиентах.

Формат: таблица «предположение → недостающие свидетельства → способ проверки».
Если мой текст не содержит фактов о реальных пользователях, напиши это прямо.

МОИ ФАЙЛЫ:
[вставить содержимое трёх собственных файлов]
```

## P02. Редактор интервью, ищущий наводящие вопросы

```text
Ты — методист качественных клиентских исследований.

Проанализируй мой сценарий интервью.
Для каждого вопроса:
- определи, не содержит ли он навязанного ответа;
- не рекламирует ли будущий продукт;
- не предлагает ли фантазировать о будущем вместо описания прошлого;
- предложи более нейтральную версию;
- добавь один вопрос-уточнение о недавнем конкретном эпизоде.

Не подсказывай респонденту выгодную основателю оценку.
Не дополняй сценарий вопросами о конфиденциальной информации,
которая не нужна для исследовательской цели.

Верни таблицу:
ID | исходный вопрос | риск | улучшенная версия | уточнение.

СЕГМЕНТ И МОИ ВОПРОСЫ:
[вставить ICP и черновик вопросов]
```

## P03. Доказательный разбор синтетических интервью

```text
Ты — исследовательский ассистент. Входные данные — учебный CSV
с 12 ИСКУССТВЕННЫМИ заметками, ID I01–I12.
ЭТО НЕ РЕАЛЬНОЕ ИССЛЕДОВАНИЕ РЫНКА.

Предполагаемый сегмент (ICP):
небольшие B2B-поставщики оборудования с несколькими
сотрудниками продаж, регулярными заказами и проблемами
при правках счетов / информировании о заказах.

Для КАЖДОГО ID выведи:
1. Подходит ли сегменту: да / нет / неизвестно.
2. Есть ли конкретный прошлый эпизод: да / нет / неясно.
3. Назван ли обходной способ: да / нет / неясно.
4. Есть ли свидетельство уже понесённых расходов или затрат времени.
5. Кто может одобрить покупку и подтверждены ли полномочия.
6. ОДИН буквальный фрагмент из записи, подтверждающий ключевой вывод.
7. Что остаётся неизвестным и что спросить дальше.

Запрещено:
- сочинять цитаты, деньги, договорённости и клиентские имена;
- приравнивать бюджет на другой инструмент к покупке нашего сервиса;
- считать будущие обещания фактом оплаты;
- объединять несколько ролей и сегментов в одну группу без оговорок;
- делать вывод, что спрос доказан.

Если поле не содержит сведения, напиши "НЕТ СВИДЕТЕЛЬСТВА".
В конце укажи ошибки, которые ты сам мог допустить,
и три способа проверить их по исходному CSV.
```

## P04. Поиск отрицательных свидетельств и опровержений

```text
Ты — независимый критик продуктовой гипотезы.

Гипотеза:
маленьким B2B-поставщикам оборудования нужен платный
ИИ-сервис анализа повторных клиентских обращений.

Работай ТОЛЬКО с предоставленным учебным CSV.
Сформируй:
A. Доказательства того, что у отдельных персонажей есть
   реальные в рамках сценария трудности (с ID и точными фрагментами).
B. Контрпримеры: задачи редки, решены без нового продукта,
   персонаж не входит в ICP, не знает проблем или не обладает бюджетом.
C. Три альтернативных объяснения тех же событий.
D. Какие реальные наблюдения опровергли бы гипотезу.
E. Какие реальные интервью надо провести следующими.

Ни один персонаж CSV не является реальным покупателем.
Не давай числовую оценку размера рынка и не объявляй
гипотезу подтверждённой.
```

## P05. JTBD по первичным данным

```text
Ты — редактор JTBD, а не генератор рекламного текста.

Используй ТОЛЬКО явно приведённые свидетельства.
Для выбранного ID собери черновик:
КОГДА [ситуация],
ХОЧУ [действие/изменение],
ЧТОБЫ [полезный результат],
ОПАСАЮСЬ [ограничение/риск].

Для каждого элемента приведи:
- буквальный фрагмент и ID источника;
- статус: "прямо сказано", "интерпретация" или "неизвестно";
- один уточняющий вопрос, если элемента не хватает.

Не вписывай в JTBD продуктовую форму:
бот, подписка, ИИ-сервис, график, дашборд,
если человек сам не назвал это целью своей работы.

ИСХОДНАЯ ЗАПИСЬ:
[вставить фрагмент с ID]
```

## P06. Минимальный эксперимент без большой разработки

```text
Ты — продуктовый аналитик стартапа из 1–2 человек.
Мы пока изучаем проблему, а не строим полноценный SaaS.

Вот предполагаемый клиентский сценарий и данные с ID источников:
[вставить свои материалы]

Предложи три возможных следующих шага:
1. дополнительное реальное интервью;
2. небольшая проверка процесса на разрешённых/синтетических данных;
3. ручной concierge-пилот с человеком в контуре.

Для каждого:
- какую гипотезу он проверяет;
- какое наблюдаемое действие или число будет результатом;
- что будет считаться опровержением;
- минимальные ресурсы и ограничения;
- какие права на данные потребуются;
- что запрещено считать доказанным до пилота.

Выдели самый дешёвый ОБРАТИМЫЙ шаг.
Если данных недостаточно, выбери интервью вместо разработки.
```

## P07. Итоговый редактор доказательности

```text
Проверь мой учебный отчёт, как строгий рецензент.

Найди и перечисли:
1. Каждое утверждение о клиенте без указанного источника.
2. Каждую цитату, которую нельзя буквально найти во входных данных.
3. Смешение SYNTHETIC и REAL.
4. Выводы о причине на основании одной корреляции или рассказа.
5. Ошибочные выводы о бюджетах и оплатах.
6. Перенос опыта одного респондента на весь рынок.
7. Рекомендации, требующие доступа к персональным данным без плана защиты.

Выведи: проблема | место в тексте | почему нельзя принять |
исправленная осторожная формулировка | как подтвердить.

Не сглаживай замечания. Не дополняй отчёт выдуманными фактами.

ОТЧЁТ:
[вставить свой отчёт]
ПЕРВИЧНЫЕ ИСТОЧНИКИ:
[вставить разрешённый синтетический корпус или выдержки]
```

## P08. Тренировочное интервью с виртуальной персоной — ТОЛЬКО репетиция

```text
Это РОЛЕВАЯ ИГРА для тренировки формулировок.
Ты изображаешь ВЫМЫШЛЕННОГО руководителя малого B2B-поставщика.
Все события, имена, суммы и ответы являются СИМУЛЯЦИЕЙ.
Они не считаются исследованием рынка и не должны
попасть в файл REAL evidence.

Отвечай кратко, иногда "не знаю".
Если я задаю наводящий вопрос — в конце поставь метку [ВЕДУЩИЙ ВОПРОС].
Если я спрашиваю о реальном прошлом эпизоде — придумай
учебный, но пометь его [СИМУЛЯЦИЯ].
После пяти моих вопросов дай обратную связь по технике интервью,
не утверждая ничего о настоящем спросе.
```

**Рекомендуемый порядок:** P01 → P02 → ручное чтение → P03 → P04 → P05 → P06 → P07.  
P08 допускается только как разминка, а не как исследование рынка.
