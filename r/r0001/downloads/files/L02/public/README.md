# AI-Native Startup · Урок 02 · Комплект v1.0

**Название:** Поиск проблемы, за решение которой платят  
**Программа:** 12 основных уроков за 6 недель, 2 факультативных углублённых занятия  
**Дата:** 14 октября 2026 года  
**Статус:** производственный комплект, готов к учебному пилоту; ещё не апробирован  
**Продолжительность занятия:** 100 минут · **Домашняя работа:** 30–45 минут активных действий

> Памятка ученика — публичная выдержка из README комплекта (EP-0001). Разделы для преподавателя и состав архива хранятся в редакционной версии.

## Главный результат

Участник приходит не с красивой презентацией будущего ИИ-продукта, а с **узким ICP, рабочей JTBD-гипотезой, качественными вопросами для интервью, реестром свидетельств, контрпримерами и планом настоящей проверки спроса**.

> Вся статистика и все персонажи демонстрационного корпуса **искусственные**. Они не подтверждают существование рынка или готовность платить.

## Для ученика

1. Прочитать `01_УЧЕБНАЯ_ГЛАВА.md`.
2. Взять три файла сквозного проекта из урока 01 (если собственных ещё нет — пустые шаблоны на странице «Практика» урока 01).
3. Заполнить `02_РАБОЧАЯ_ТЕТРАДЬ.md`.
4. Вручную разобрать часть `data/interview_notes_12_unlabeled.csv`, затем сравнить с ИИ по `PROMPTS.md`.
5. Заполнить новые файлы `04_customer_profile.md`, `05_interview_guide.md`, `06_evidence_register.csv`, `07_problem_decision.md` в своей папке проекта.
6. Организовать первые **реальные** разговоры с подходящими людьми. Если контакта нет, честно оставить гипотезу без подтверждения.

## Связь с первым уроком

Урок 01: `гипотеза → workflow → предполагаемые метрики`.  
Урок 02: `узкий ICP → реальные интервью → JTBD → свидетельства → решение о проверке`.  
Урок 03: `минимальный пилот → действия клиента → оценка интереса к оплате`.

Файлы 01–03 **не перезаписывайте** при копировании новых шаблонов. Пустые версии файлов 01–03 — в уроке 01.

## Достоверность и этика

Различайте:
- `SYNTHETIC`: придуманный учебный пример;
- `REAL`: беседа с человеком при законном и прозрачном использовании заметок;
- `INFERENCE`: аналитическое объяснение, требующее проверки;
- `NOT_YET_VALIDATED`: пока никаких реальных подтверждений.

Для реального исследования не нужно собирать или загружать в общий проект чужие имена, телефоны, записи звонков и закрытые документы. Правила защиты данных и ссылки — в `06_ИСТОЧНИКИ_И_ОБНОВЛЕНИЯ.md`.

## Критерии завершения

- Сегмент и роли ясно описаны.
- Вопросы направлены на **прошлое поведение**.
- В анализе есть реальные ссылки на `ID` источников, контрпримеры и недостающие сведения.
- Никто не назвал искусственные записи реальными интервью.
- Сформулирован небольшой следующий шаг с собственником решения и ограничениями на данные.
