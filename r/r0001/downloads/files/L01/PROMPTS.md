# Библиотека запросов · Урок 01

Все запросы предназначены для работы с **учебными данными**. Не вставляйте реальные клиентские записи без разрешения.

## P1 · Факты, гипотезы, варианты

```text
Ты помогаешь основателю маленького IT-стартапа.

Учебный набор: за неделю пришло 100 обращений:
40 — изменение заказа; 25 — срок доставки;
15 — ошибка в счёте; 12 — характеристики товара;
8 — прочее.

Наша цель — уменьшить ненужные обращения,
не ухудшая возможность совершить покупку.

1. Назови только факты, которые следуют из цифр.
2. Предложи три гипотезы о возможных причинах.
3. Для каждой гипотезы придумай дешёвый способ проверки.
4. Сравни: ИИ-оператор, инструкция, изменение процесса.
5. Предложи показатели успеха и показатели риска.
6. Отметь всю неизвестную информацию.

Не выдавай предположения за доказанные причины.
Ответ оформи компактной таблицей.
```

## P2 · Проверка и фальсификация

```text
Проведи критическую проверку собственного ответа из P1.

Для трёх самых важных утверждений укажи:
1. Точный текст утверждения.
2. Статус: факт, гипотеза, рекомендация.
3. Какое наблюдение могло бы опровергнуть утверждение.
4. Какие данные отсутствуют.
5. Дешёвый и разрешённый способ проверки.

Не придумывай результаты не проведённых экспериментов.
```

## P3 · Недорогой проверяемый эксперимент

```text
На основании уже обсуждённых гипотез предложи
ОДИН минимальный эксперимент на одну неделю.

Назови:
- гипотезу;
- целевую группу;
- изменение;
- подготовительные условия;
- измерение успеха;
- измерение возможного вреда;
- критерий остановки;
- владельца решения и кто утверждает изменение;
- данные, которых пока нет.

Если исходной информации недостаточно, назови пробел.
Пиши как план, не изображай эксперимент завершённым.
```

## P4 · Первое описание собственного стартапа

```text
Я хочу создать микро-IT-стартап из одного или двух человек.

Моё описание проблемы: [ВСТАВЬ СВОЮ ГИПОТЕЗУ].

Помоги оформить:
1. предполагаемого клиента и ситуацию;
2. желаемый outcome — полезное изменение;
3. workflow из 5–7 действий;
4. исполнителя каждого шага:
   человек / ИИ с проверкой / обычная программа;
5. проверяемый выход каждого шага;
6. основные риски и неизвестные данные;
7. одну лишнюю операцию, которую можно пока исключить.

Не предлагай разработку, пока не сформулирован клиентский результат.
Все предположения явно помечай как гипотезы.
```

## P5 · Редактор артефактов (не выполняет действия)

```text
Проверь три черновика файлов:
01_startup_hypothesis.md,
02_workflow_map.md,
03_success_metrics.md.

Не изменяй их без моего разрешения.
Сообщи:
- нет ли противоречий;
- где перепутаны output и outcome;
- каких данных не хватает;
- какие обещания нельзя пока проверить;
- какие шаги в workflow лишние;
- по каким критериям можно принять результат.

Вначале дай замечания с указанием конкретного файла и раздела,
затем — минимальный список правок по приоритету.
```

## P6 · Пять вопросов для интервью

```text
Составь пять открытых вопросов к потенциальному клиенту:
[ТИП КЛИЕНТА, ПРЕДПОЛАГАЕМАЯ ПРОБЛЕМА].

Вопросы должны выяснять прошлое реальное поведение,
последний случай проблемы, текущий способ решения
и затраты времени или денег.

Не спрашивай «купили бы» и «нравится ли идея»
как единственное основание для вывода о спросе.
После вопросов напиши, какой ответ был бы
сигналом против моей гипотезы.
```

## Как пользоваться

1. Начните с P1 на примере.
2. Проверьте результат через P2.
3. Разработайте план P3.
4. Перейдите к своему проекту через P4.
5. Заполните файлы вручную или с участием ИИ, проверяя каждое поле.
6. Проведите самопроверку P5, затем подготовьте вопросы P6.

Никакой промпт не делает гипотезу фактом и не заменяет общение с клиентом.
