# Набор данных: 100 учебных обращений

**Источник:** полностью синтетический набор, созданный авторами курса 14.10.2026.  
**Назначение:** учить отличать сообщения клиентов, их классификацию и доказанную причину проблемы.  
**Личные данные:** отсутствуют.

## Файлы

- `obrashcheniya_100.csv` — 100 записей с учебными категориями и подтипами: контрольный эталон (в материалах преподавателя, на сайте не публикуется).
- `obrashcheniya_100_bez_metok.csv` — те же обращения **без** категорий: для самостоятельной классификации ИИ или вручную.

Формат обоих CSV — UTF-8 с BOM для удобного открытия в некоторых версиях Excel; разделитель `,`.

## Поля

| Поле | Смысл |
|---|---|
| `id` | Синтетический идентификатор сообщения, C001–C100 |
| `канал` | Учебный канал обращения: сайт, почта, чат, телефон |
| `обращение` | Придуманный текст сообщения |
| `категория_учебная` | Крупная категория, назначенная при создании набора |
| `подтип_со_слов_клиента` | Уточнение того, что клиент **сообщил**, не доказанная причина |
| `статус_причины` | Везде «не проверена» |

## Точные итоговые частоты

| Категория | Число |
|---|---:|
| Изменение заказа | 40 |
| Срок доставки | 25 |
| Ошибка в счёте | 15 |
| Характеристики товара | 12 |
| Прочее | 8 |
| **Всего** | **100** |

Категории взаимоисключающие **в этом специально сконструированном примере**. В реальных переписках одно обращение может содержать несколько проблем, поэтому потребуется явно определить способ множественной классификации.

## Что набор доказывает и не доказывает

Набор доказывает только внутренние искусственно заданные счётчики. Он **не** доказывает ничего о реальном рынке, популярности проблем, репрезентативности, намерениях клиентов, причинах ошибок интерфейса, вероятной выгоде от разработки или будущем росте продаж.

**Особая ловушка:** «40% обращений об изменении заказа» ≠ «40% покупателей не смогли изменить заказ». Для второй доли требуется количество уникальных покупателей и информация об их опыте, которых в данных нет.

## Короткое упражнение для опытных участников

1. Классифицируйте `obrashcheniya_100_bez_metok.csv` с помощью ИИ.
2. Сохраните для каждого id предложенную категорию и уровень уверенности.
3. Сравните с контрольной разметкой (файл `obrashcheniya_100.csv` у преподавателя) через обычный код или таблицу.
4. Выпишите ошибки и неоднозначные случаи.
5. Объясните, почему совпадение с учебными метками **не гарантирует** правильную диагностику реального процесса.
